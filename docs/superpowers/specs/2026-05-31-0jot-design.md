# 0jot — code markers to GitHub issues (PDD-like)

**Date:** 2026-05-31
**Status:** Design approved, ready for implementation plan
**Form:** GitHub Action for `0nybl` Rust repositories (no AI)

## Summary

0jot scans a repository's source for `@todo` markers and keeps GitHub issues in
sync with them: a new marker opens an issue, and removing the marker from the
code closes its issue. It is the second tool in the `0nybl` fleet (after eerk).

Marker↔issue matching uses a **fingerprint embedded in the issue body** — the
GitHub issues themselves are the state. 0jot never writes to the code (no issue
numbers injected, no commits). Issues are created/closed by a **dedicated `0jot`
GitHub App** (`0jot[bot]`) — separate from eerk's `0eerk` App, with its own org
secrets, so 0jot's activity is attributed to its own bot identity.

Naming: the repository and command are `0jot`. Because a Rust crate name cannot
begin with a digit, the Cargo package and lib are named `jot`, and the binary
target is named `0jot` (`[[bin]] name = "0jot"`).

## Goals

- New `@todo` marker → a GitHub issue is opened.
- Marker removed from code → its issue is closed.
- Idempotent: re-running with unchanged code makes no changes.
- Code is read-only: no write-backs, no bot commits to the repo.
- Pure, offline-testable engine. Zero AI.

## Non-Goals

- No estimates / time factor in markers (deliberately dropped).
- No editing of existing issues' titles/bodies after creation.
- No writing issue numbers back into source.
- Not multi-language-aware beyond comment-prefix stripping (see Marker grammar).

## Marker grammar

A marker is a line whose comment text begins with the token `@todo:` followed
by a title, optionally followed by indented continuation comment lines that
form the issue body.

```rust
// @todo: Replace the bubble sort with a real allocator
//   The current placeholder is O(n^2) and only here to compile.
//   Swap for a free-list before the linker work lands.
```

Rules:

- **Recognition:** strip a leading comment prefix from the line, then match
  `@todo:` (case-sensitive) at the start of the stripped text. Comment prefixes
  recognized (language-agnostic): `//`, `#`, `*`, `;`, `--`, plus any leading
  whitespace and an optional `/*`. This makes the marker usable in `.rs` and in
  most other text files without per-language parsing.
- **Title:** the rest of the marker line after `@todo:`, trimmed. Empty title →
  the marker is ignored (not a valid marker).
- **Body:** consecutive following lines that are (a) comments (same prefix
  family) and (b) indented deeper than the `@todo` token's column. Collected
  until the first line that is not a deeper-indented comment. Leading comment
  prefix and the common indentation are stripped from each body line.
- One marker per `@todo:` occurrence. Multiple markers in one file are allowed.

## Fingerprint

`fingerprint = first 12 hex chars of sha256(normalized_title)` where
`normalized_title` is the title with surrounding whitespace trimmed and internal
runs of whitespace collapsed to single spaces.

- Based on the **title only**, not file/line — moving or reformatting code does
  not recreate the issue.
- **Caveat:** two markers with identical normalized titles collapse to one
  fingerprint → one issue. Documented behavior; authors keep titles distinct.

## Issue shape

- **Title:** the marker title.
- **Body:**

  ```
  <body lines, if any>

  ---
  Found at `path/to/file.rs:42`

  <!-- 0jot: <fingerprint> -->
  ```

- **Label:** `todo` (auto-created by the workflow if absent).

The trailing HTML comment carries the fingerprint and is how 0jot recognizes
its own issues on later runs.

## Architecture

### Engine (Rust binary `0jot`, pure)

Single subcommand:

```
0jot plan --repo <dir> --issues <issues.json> --out <actions.json>
```

- **Scan:** walk `<dir>`, skipping `.git`, `target`, `node_modules`, and any
  file that is not valid UTF-8. Parse markers per the grammar above into
  `Marker { fingerprint, title, body, file, line }`.
- **Existing issues:** read `<issues.json>` — an array the workflow assembles
  via `gh`, each `{ number, body }` for open issues labeled `todo`. Extract each
  issue's fingerprint from its `<!-- 0jot: ... -->` marker (issues without one
  are ignored).
- **Diff → actions:**
  - `create` = markers whose fingerprint matches no open issue.
  - `close` = open `todo`-issues whose fingerprint matches no current marker.
- **Output:** `actions.json`:

  ```json
  {
    "create": [
      { "title": "...", "body": "...", "fingerprint": "abc123def456",
        "file": "src/x.rs", "line": 42 }
    ],
    "close": [ { "number": 7, "fingerprint": "deadbeef0000" } ]
  }
  ```

  The `create` entries' `body` is the fully-rendered issue body (including the
  `Found at` line and the hidden fingerprint comment), so the workflow passes it
  straight to `gh issue create`.

All file I/O is local; no network in the binary → fully offline-testable with
fixture repo dirs and fixture `issues.json`.

### Workflow (`0jot.yml`, seeded into each repo)

Triggers: `push` to the default branch + `workflow_dispatch`.

1. **Mint app token** (`actions/create-github-app-token`, org secrets
   `JOT_APP_ID` / `JOT_APP_PRIVATE_KEY` — the dedicated `0jot` App). The App
   needs Repository permissions **Issues: read & write** and **Contents: read**,
   installed org-wide on `0nybl`. Issues are attributed to `0jot[bot]`.
2. **Checkout** the repo.
3. **Install** `0jot` (`cargo install --git https://github.com/0nybl/0jot --tag <ver> --bin 0jot`).
4. **Fetch issues:** `gh issue list --label todo --state open --json number,body > issues.json`.
5. **Plan:** `0jot plan --repo . --issues issues.json --out actions.json`.
6. **Apply:**
   - ensure the `todo` label exists (`gh label create todo --color ... --force || true`);
   - for each `create`: `gh issue create --title ... --body ... --label todo`;
   - for each `close`: `gh issue close <number> --comment "Resolved: @todo marker removed from code."`.

All network/issue mutation lives in the workflow; the binary only computes the
plan.

## Components & boundaries

- **`marker` module** — parse one file's text → `Vec<Marker>`. Pure.
- **`scan` module** — walk a dir, apply `marker` to each UTF-8 file. Pure (fs read only).
- **`fingerprint` module** — title normalization + sha256. Pure.
- **`issues` module** — parse `issues.json`, extract fingerprints. Pure.
- **`plan` module** — diff markers vs issues → `Actions`. Pure.
- **`main`** — clap CLI, wiring, JSON read/write.
- **Workflow `0jot.yml`** — orchestration + all `gh` calls.

## Testing

- `marker`: title-only, title+body, indentation boundaries, non-marker comments,
  empty title ignored, multiple markers per file, different comment prefixes.
- `fingerprint`: whitespace normalization, stability, collision of equal titles.
- `issues`: extract fingerprint from body, ignore issues without the marker.
- `plan`: create-only, close-only, no-op (unchanged), mixed.
- Integration: fixture repo dir + fixture `issues.json` → expected `actions.json`
  (golden file); binary exits 0.
